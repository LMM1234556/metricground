# MetricGround 生产化与迭代路线

## 目标边界

本路线的目标是将本地 MVP 提升为可部署、可恢复、可观测、可回滚的单用户或小规模可信分析 Agent。它不承诺企业级多租户、任意数据源和无限规模。

## v0.1.0：可复现的本地基线

验收条件：

- Git 保存真实代码历史并使用语义化版本标签；
- 静态检查、构建、确定性测试和浏览器回归进入 CI；
- README、能力矩阵、版本说明和已知限制一致；
- 不提交原始私有数据、凭据、运行时目录和本地环境文件。

## v0.2.0：可恢复的任务执行（已完成）

### 部署前置修复

- 冻结 Node 22.13 运行版本并排除 Node 24 + Vinext 本地开发服务异常；
- DuckDB-WASM 的 Worker 与 gzip 压缩 WASM 由构建流程发布为同源资源；不支持浏览器端流式解压时才回退固定版本 CDN；
- 增加部署后的首页、规划 API 和 DuckDB 加载烟雾测试。

### 数据模型

只持久化执行元数据，默认不保存上传文件的原始数据行：

- `task_runs`：问题、状态、AnalysisSpec、数据版本摘要、结果摘要；
- `task_events`：状态转换的追加式事件；
- `tool_calls`：工具名称、输入摘要、状态、耗时和错误；
- `approvals`：人工确认类型、决策、说明和时间；
- `evidence_artifacts`：证据包校验和、版本和存储位置。

### 运行保证

- 创建任务和批准执行使用幂等键，重复请求不产生重复计算；
- 每次任务具有 `taskRunId`，每次请求具有 `traceId`；
- 页面刷新后可以恢复最近任务；
- 模型超时可以安全降级，确定性计算失败不会被伪装成成功；
- 数据版本变化时继续阻断旧计划执行；
- 健康检查区分 Web、数据库和模型提供方状态。

### 验收测试

1. 规划完成后刷新页面，任务状态、计划和审批记录仍存在；
2. 同一幂等键重复提交两次，只产生一次执行记录；
3. 模型不可用时记录降级原因，并继续走规则允许的安全路径；
4. 数据库不可用时返回可恢复失败，不生成虚假结果；
5. 数据版本变更后，旧计划不能继续执行；
6. 日志包含 traceId，但不包含原始数据行和模型密钥。

## v0.3.0：部署前安全与恢复闭环（已完成本地验收）

- API 分路由限流、请求 ID、结构化日志、载荷上限和同源写入校验；
- CSV/XLSX 文件类型、二进制空字节、10 万行和 200 列边界；
- TaskRun 所有者绑定，支持在受信 Sites 身份头和环境开关下强制认证；
- Web、D1 和可选模型提供方健康状态；数据库故障不绕过限流；
- D1 导出、SHA-256 清单、隔离目录恢复和关键表行数对账；
- 所有者隔离、跨站写入、超限请求和频率限制进入 API 回归。

本版本只证明本地生产构建预览中的防护与恢复路径；在受信平台完成真实登录、远程 D1、日志平台和公网烟雾测试前，不能宣称生产上线。
