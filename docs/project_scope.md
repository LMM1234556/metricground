# 项目定位与验收边界

## 用户问题

业务人员即使拥有 Excel、CSV 或数据库，也常因不熟悉 SQL、指标定义不一致、表粒度混淆和结果缺少验证而难以获得可信结论。

## 目标用户

- 需要临时分析经营数据的运营、销售和产品人员；
- 需要快速完成初步探索、但仍希望保留查询依据的数据分析人员。

## 核心流程

`提出问题 → 识别口径与范围 → 必要时澄清 → 生成只读查询 → 执行分析 → 复算校验 → 输出结论、证据与限制`

## MVP 验收标准

1. 能回答预设 Olist 经营问题，并展示所用口径和数据范围；
2. 涉及订单与商品一对多关系时，不错误放大订单量；
3. 涉及 GMV 时明确其为已送达订单商品金额，不含运费且不等于收入或利润；
4. 涉及 2018 年全年对比时提示数据仅覆盖至 8 月，并建议同期比较；
5. 只允许只读分析查询，拒绝数据修改请求；
6. 对观察性分析不输出无证据的因果结论；
7. 使用固定问题集记录正确率、口径命中率、限制提示率与平均响应时间；
8. 与未加入业务约束的基线版本进行同题对比。

## 不纳入首版

- 企业级权限、审计与多人协作；
- 对任意行业和任意数据库的完全泛化；
- 自动替代分析师作出最终经营决策。
