# MetricGround PRD：初级数据分析师可信经营分析 Agent

## 1. 产品定位

MetricGround 面向使用 Excel、CSV 处理常见经营数据的初级数据分析师。产品不替代分析师作出业务决策，而是帮助用户理解数据结构、发现质量风险、明确指标口径、生成可复核分析并解释结论边界。

首版只支持本地 Excel/CSV，不接入企业数据库，不处理非结构化文档，不声称适用于所有行业。

## 2. 核心用户与问题

### 核心用户

- 能使用 Excel 或基础 SQL/Python，但缺少真实业务分析经验的初级数据分析师；
- 需要临时分析结构化经营数据的运营、产品和销售人员。

### 重点问题

1. 不确定一行数据代表订单、商品、用户还是一次行为；
2. 不知道重复、缺失、类型异常和时间覆盖是否会影响结论；
3. 多表连接后可能放大订单数、金额或均值；
4. 指标缺少分子、分母、去重单位、过滤条件和时间口径；
5. 代码能够运行，但不知道结果是否与业务定义一致；
6. 容易将不完整周期直接比较，或将观察性关联写成因果关系。

## 3. MVP 用户流程

```text
上传 Excel/CSV
  -> 文件解析与字段画像
  -> 候选主键和数据粒度判断
  -> 数据质量检查
  -> 用户提出业务问题
  -> Agent 生成分析计划并提出必要澄清
  -> 用户确认指标口径和处理动作
  -> 受控工具执行确定性计算
  -> 结果对账与风险校验
  -> 输出结论、图表、代码、口径卡和限制
```

## 4. 功能需求

### F1 文件接入

- 支持 `.csv` 和 `.xlsx`；
- CSV 首版上限 20 MB，Excel 首版上限 10 MB；
- Excel 支持选择工作表；
- 文件默认仅在本地或当前分析会话中处理；
- 上传后展示文件名、工作表、行数、列数和读取状态；
- 解析失败时说明编码、格式、文件大小或空表等具体原因。

### F2 字段画像与粒度识别

- 展示字段名、推断类型、缺失率、唯一值数和示例值；
-识别候选日期、金额、类别和标识字段；
- 根据唯一性提出候选主键和复合主键；
- 使用清晰语言解释“当前一行可能代表什么”；
- Agent 只能提出候选粒度，必须由用户确认。

### F3 数据质量体检

- 检查完全重复行、候选主键重复、缺失值和混合类型；
- 检查日期解析失败、异常时间范围和明显越界值；
- 对金额、比率和数量字段进行基础分布与异常值提示；
- 每个问题展示证据、影响、建议动作和严重程度；
- 删除、填补、类型转换等改变数据的动作必须获得用户确认；
- 不覆盖原始文件。

### F4 指标口径确认

- 首版支持计数、金额、平均值和比率四类指标；
- 指标卡至少包含名称、业务含义、公式、统计粒度、去重单位、时间字段、过滤条件、金额范围和限制；
- 当口径缺失时，Agent 应追问而不是直接计算；
- 检查 GMV 与收入/利润混用、不完整周期比较和观察性因果措辞。

### F5 受控分析

- Agent 先输出分析计划，再选择白名单工具；
- 由 pandas 或 DuckDB 执行确定性计算，大模型不直接生成最终数字；
- 首版支持分组聚合、筛选、排序、时间趋势、Top N 和基础分组对比；
- 不执行文件写入、系统命令和数据库修改语句；
- 超出支持范围时明确拒答并说明缺少的数据或工具。

### F6 结果与证据

- 输出直接结论、指标数值、图表和通俗解释；
- 展示使用的数据范围、过滤条件、统计粒度和计算公式；
- 提供可复制的 pandas 代码与通用 SQL 参考；
- 展示数据质量风险、假设和结论限制；
- 支持导出分析摘要和指标口径卡。

## 5. Agent 决策边界

大模型负责理解问题、提出澄清、生成计划、选择工具和解释结果。确定性程序负责读取数据、计算指标、执行检查和生成证据。

以下动作不得自动执行：

- 删除行或列；
- 填补缺失值；
- 修改字段类型并覆盖源数据；
- 根据模糊字段名直接认定业务含义；
- 执行任意 Python、系统命令或写入型 SQL；
- 将观察性结果表述为已经证明的因果结论。

## 6. 非功能要求

- 失败信息必须可理解且可恢复；
- 分析过程可追溯，至少保存问题、口径、步骤和校验结果；
- 页面适配桌面端，关键流程兼容移动端查看；
- 文件处理不应在未经说明的情况下上传第三方服务；
- 页面中明确说明 AI 建议需要用户和业务负责人确认。

## 7. MVP 验收标准

1. 成功读取至少 3 份结构不同的真实或公开 Excel/CSV；
2. 正确展示每份数据的行列数、字段类型、缺失率和唯一值；
3. 在预设测试数据中发现重复订单、主键重复、混合类型和日期缺失；
4. 对订单表与商品明细表明确提示粒度差异和重复统计风险；
5. 未确认关键指标口径时不直接输出数字；
6. 四类指标的计算结果能够由独立 pandas 脚本复算一致；
7. 对不完整年度比较、GMV 概念混用和因果越界给出正确提示；
8. 不支持问题不会返回无关默认答案；
9. 原始文件在整个流程中保持不变；
10. 至少建立 30 道任务题，覆盖正常、歧义、错误和拒答场景；
11. 至少邀请 2 名目标用户完成上传到导出的完整任务，并记录失败点；
12. GitHub 仓库提供安装、启动、测试、数据来源和项目边界说明。

## 8. 暂不纳入首版

- MySQL、PostgreSQL 等数据库直连；
- 多人协作、权限、审计和企业指标中心；
- 预测、机器学习建模和自动经营决策；
- 任意 Python 代码执行；
- PDF、图片、网页和自然语言文档分析；
- 对所有行业业务语义的自动识别。

## 9. 成功标准与简历口径

首版成功不以页面数量或模型回答长度衡量，而以以下结果衡量：

- 用户能用一份此前未接入的表格完成一次可信分析；
- 系统能在计算前暴露关键数据与口径风险；
- 输出可以通过独立代码复算；
- 新用户能够理解为什么这样计算以及结论不能说明什么。

在以上验收完成前，项目只能描述为“固定 Olist 场景的受控经营分析 Agent”。完成后可以描述为“支持 Excel/CSV 的初级数据分析师可信分析 Agent”，但仍不能宣称为生产级企业数据平台。
