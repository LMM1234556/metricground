# MetricGround v0.3.10

两份首轮用户结果暴露了同一交接问题：用户不理解单指标合同，地区比较经质量/清洗后被引导成单指标平均金额；清洗范围变化也未进入最终证据。数学对账通过不能弥补目标不一致。

本版本按原计划选择确认页，地区/趋势/排名进入经营分析；清洗后保留原问题与字段候选，旧审批不用于新版本。派生任务链接原任务与源数据版本，沿用规划元数据明确标记未新增模型请求。原问题不再被指标名称覆盖。

口径页面新增可读草案，说明统计对象、计算方式和当前文件范围；数量名称配金额/平均公式在生成与执行层拦截。明确要求计数的原问题不能无提示变成另一种单指标；修改目标应开始新分析。

清洗后的行数、非空唯一编号和删除规则随任务保存；范围重新确认前不允许执行。证据格式1.4展示source/derived版本、sourceTaskId、删行规则与confirmedAt，继续兼容旧文件；历史缺失内容不回填。

[完整CI 38133451599](https://github.com/LMM1234556/metricground/actions/runs/38133451599)通过静态与浏览器门，包括新增任务保持/范围门禁、旧清洗流程、移动复核、双格式下载、持久化、隔离和恢复。首两次CI暴露旧测试使用数量名称测比例、未确认新范围门禁等问题，调整为明确的新任务和范围确认后重跑；安全检查保留。

公开Sites版本14部署成功，健康检查为v0.3.10、Web/D1正常。原问题“比较不同地区的表现”的公网规则探针为group_compare、clarify、经营分析，model=null；预算保持17/20，剩3次。本轮测试和探针未发付费模型请求。

自动回归证明流程约束生效，用户能否理解草案仍需修复后回测。两份首次失败保留在 `evaluation/user_test_round1/observations_round1.md`，回测材料在 `evaluation/user_test_round2/`。
