# MetricGround v0.3.7

本轮来自同一 TaskRun 的真实交付文件复核：计算、数据版本和完整 DuckDB SQL 均正确，但报告与审计 JSON 由两次下载动作生成了不同快照；三项质量风险仍显示未判断，指标批准不能替代质量处置。

## 改动

- 已完成任务以进入 `COMPLETED` 的时间和内容为不可变证据快照；下载动作继续写入持久化审计记录，但从报告/JSON证据内容中排除。
- 报告和 JSON 从同一快照生成，任务编号、快照时间、工具记录和校验和保持一致。
- 分组/趋势/Top N与单指标计算均增加质量执行门禁；全部风险需要人工逐项决定，批准清洗时必须先确认派生副本。
- 浏览器回归先证明未判断风险时按钮被禁用，再完成三项决定、执行计算、下载双格式文件并核对相同校验和。

## 验收与边界

[完整 CI 38056124877](https://github.com/LMM1234556/metricground/actions/runs/38056124877) 的静态质量门和浏览器回归均通过；公开 Sites 版本 11 健康检查显示 v0.3.7、Web/D1 正常。模型状态 `configured` 只说明配置存在，本轮没有模型请求，也不证明模型准确率。

同项目内主引擎与 DuckDB 对账仍不等于第三方独立审计；校验和只证明证据内容未发生不一致变化，不证明源数据真实性或业务定义正确。
