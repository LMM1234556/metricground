# v0.3.12 — 一对多关联的左表粒度保持

2026-10-13。针对P05“把商品品类补到订单信息”的实际阻塞补充安全执行分支，不改写P05首次失败记录。

## 本版本范围

- 当左表关联键唯一、右表同一键多行，且用户选择Left join并要求保留左表粒度时，系统不再只提示改成明细粒度或Inner join。
- 用户选择需要补充的右表描述字段后，浏览器确定性引擎先按右键生成非空去重列表，再与左表做Left join。
- 右表数值和日期字段不允许进入该方案，避免系统擅自决定求和、平均、最大值或其他业务口径。
- 未匹配左表记录保留，补充字段为空；未匹配右表记录不附加到任何左表记录并明确提示。
- 执行后验证输出行数等于左表行数、原始关系仍为一对多、版本未漂移、未匹配左表记录保留，以及左表常见金额字段守恒。
- 派生数据版本和导出证据保存源版本、左右键、所选字段、预聚合键数、匹配键数、孤儿行数和输出行数。

## 样例预期

`join_orders_sample.csv`为4行订单，金额合计410；`join_items_sample.csv`为5行明细，其中O-1001有A、B两个品类，O-X无法匹配订单，O-1004没有商品明细。

安全方案输出4行订单：O-1001的品类字段为`A、B`，O-1004品类为空；金额仍为410。直接Left join会输出5行并把O-1001金额重复累计，因此仍不会获准作为“一行一订单”结果。

## 当前验证与边界

本地类型检查、构建、静态质量门和55项关联规则断言已通过；云端浏览器CI及Sites发布状态待本版本提交后补记。测试不调用真实模型。

当前只覆盖双表、一对多、Left join和右侧描述字段去重列表。它不是通用预聚合器，不支持右表数值/日期自动汇总、按品类分摊订单金额、N:N关系或三表预聚合。工程通过不代表P05参与者已完成复测。
