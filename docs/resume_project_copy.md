# 简历项目文案

## 推荐版本

**MetricGround｜可信电商经营分析 Agent｜个人项目**

**技术栈：** Python、pandas、SQL、React、TypeScript、Qwen3:8b、Ollama、DuckDB-WASM、Cloudflare D1

- **产品与数据设计：** 面向使用 Excel/CSV 的初级分析师，设计“数据画像—质量检查—口径确认—受控计算—结果验证”流程，覆盖单指标、分组比较、日/周/月/季度趋势、Top N 及最多三表关联。
- **Agent 架构：** 实现规则路由、本地 Qwen3:8b 适配器与受限 Qwen-Plus 云规划，以 `AnalysisSpec` 与 `TaskRun` 约束字段绑定、人工审批、工具调用和失败状态；数字由白名单确定性引擎计算，并由 DuckDB-WASM 独立 SQL 复算。明确意图优先规则，不执行任意生成 SQL/Python。
- **数据处理与可信分析：** 使用 pandas 清洗并关联 9 张 Olist 业务表、约 156 万行记录，先将商品明细聚合至订单粒度，复算订单量、GMV、客单价和负面评价率，完成主键、连接完整性及 8 项指标对账检查。
- **可信关联与测评：** 识别 1:1、1:N、N:1、N:N、孤儿键和行数膨胀，默认阻止 N:N；使用来源行血缘对账关联前后金额并阻止不安全聚合。构建 30 题意图集及订单/营销/库存固定任务，在自建范围内完成独立 pandas 复算和浏览器回归。
- **工程化迭代：** 将 TaskRun、审批和验证摘要持久化到 D1，加入幂等写入、乐观并发、条件式账号隔离、API 限流与载荷边界；建立 D1 导出、SHA-256 清单和隔离恢复演练，并以静态/API/浏览器三层门禁验证版本。

> 当前可以写“完成新人引导自动化验收和测试方案”，不能写“已通过 5 名新人测试”。项目所有者手工走通 3 份合成文件只属于冒烟测试。

> v0.3.3 迭代案例：发现口语计数误路由、排名被澄清逻辑改成单指标、缺字段错误替代，补充 24 个路由用例、15 个实际 API 用例和页面交接断言；完整 CI 与 10 个线上匿名探针通过。属于需求发现—修复—回归—发布证据，不是大模型准确率。

> v0.3.4 可补充：为云模型增加全局请求计数、每问题调用上限、输出限制与失败用量摘要，关闭重复重试；完成三个本地真实 Qwen-Plus 工具层探针与完整 CI。必须注明公开模型尚未启用、三题并非盲测，不写“云模型已生产上线”或“模型准确率100%”。

> v0.3.5 的迭代证据：真实云规划初次失败 → 关闭开关保留计数 → 在 workerd 复现并修复重定向兼容差异 → 增加运行时回归 → 公网 cloud-agent 两步与 D1计数通过。v0.3.6 的迭代证据：检查用户实际交付文件发现SQL截断/元数据缺失 → 补记录与报告 → 新浏览器回归发现连续导出409 → 修复本页修订号同步且保留跨页面冲突保护 → 完整CI通过 → Sites版本10发布。可讲清楚验证驱动的迭代，不把单个探针或自建回归写成生产准确率。
