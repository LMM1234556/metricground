# MetricGround MVP 完整性审计

> **历史审计快照：** 本文记录较早版本，当时尚未实现分组、趋势、Top N、交互式多表关联和金额对账。请勿把下文未完成项当作当前状态；当前能力与边界以 [`capability_matrix.md`](capability_matrix.md) 为准。

审计目标：判断产品是否已经能够面向使用 Excel/CSV 完成常见经营分析的初级数据分析师，提供数据理解、质量检查、指标口径确认、受控计算和结果验证。

审计结论：**核心可信工作流和第一版自然语言 Agent 编排已经形成可运行 MVP，但还不是覆盖完整经营分析场景的通用 Agent，也不是生产级数据平台。** 当前可以真实演示“上传未知表格 → Agent 读取元数据并判断意图 → 字段画像 → 质量检查 → 人工选择规则 → 二次确认生成清洗副本 → 自动复检 → 指标合同 → 受控计算 → 结果校验”。

## 按优先级排列的未完成项

1. **P1：Agent 计划尚未自动调用后续执行工具。** 当前 Agent 能理解问题、检查元数据、选择工具和决定是否追问，但仍需用户点击进入质量检查或指标口径页面，不能声称已经是全自动分析 Agent。
2. **P1：通用上传数据缺少分组、时间趋势、Top N 和图表工具。** 目前能完成单指标计算，但不足以覆盖“哪个地区最高、月度趋势如何、前五商品是什么”等常见经营分析。
3. **P1：尚未完成 2 名目标用户的端到端可用性测试。** 自动化回归不能替代真实新人是否看得懂、是否会操作。
4. **P2：缺少复合键识别、多表连接放大检查、未来日期和业务合法值域规则。** 这些决定了真实工作数据的适用范围。
5. **P2：缺少完整分析摘要导出与会话历史。** 目前证据可看、代码可复制，但一次分析还不能整体留档和恢复。
6. **P2：浏览器计算没有连接真实 pandas/DuckDB 运行时。** 当前数字由 TypeScript 确定性逻辑计算，pandas 代码是可复核参考；项目文案必须保持这一边界。

## 建议的下一阶段顺序

1. 将 Agent 计划与现有质量检查、指标合同和受控计算工具串联，并在写操作前保留人工批准；

4. 完成分析摘要导出和最小会话记录；

6. 最后再写 GitHub 首页、演示视频和简历量化文案。
