# MetricGround Agent 架构基准

## 1. 冻结的产品目标

MetricGround 面向使用 Excel/CSV 完成常见经营分析的初级数据分析师，提供数据理解、质量检查、指标口径确认、受控计算和结果验证。

“Agent”不是页面名称。系统必须能够围绕用户目标读取当前数据状态、制定计划、选择白名单工具、处理工具结果、在高风险节点暂停并请求人工确认，最后输出可复核的结果与限制。

## 2. 端到端链路

```text
用户上传 Excel/CSV 并提出业务问题
  -> 数据解析器生成字段画像、候选粒度与质量摘要
  -> 策略路由器识别清晰意图；含糊意图交给本地模型
  -> Agent Planner 生成结构化计划和字段绑定
  -> 状态机逐步调用白名单工具
  -> 粒度、清洗动作、指标口径由用户确认
  -> 确定性引擎执行聚合、筛选、分组、趋势或 Top N
  -> Validator 校验数据版本、字段、行数、分母、边界与对账关系
  -> 输出结论、表格/图表、SQL/pandas、证据和限制
```

## 3. 模型与程序的职责

### 大模型负责

- 理解含糊的自然语言目标；
- 提出必要的澄清问题；
- 从真实字段清单中提出候选字段绑定；
- 组合工具调用计划；
- 基于工具返回值生成解释，不直接生成指标数字。

### 确定性程序负责

- Excel/CSV 解析、类型推断和数据画像；
- 重复、缺失、非法日期、异常值和粒度风险检查；
- 结构化筛选、聚合、分组、趋势、排序和 Top N；
- 数据版本、字段存在性、数值有效性、比例边界和结果对账；
- 关联键覆盖率、孤儿键、行数膨胀和来源行级金额守恒；
- 清洗副本与分析结果导出。

清晰且高频的意图优先由确定性策略路由，避免模型波动和不必要延迟。模型不可用时，系统只能安全降级或请求澄清，不得猜测业务含义后继续执行。

## 4. 白名单工具

| 工具 | 作用 | 是否需要人工确认 |
|---|---|---|
| `profile_dataset` | 读取数据画像、候选粒度和字段类型 | 粒度需确认 |
| `run_quality_checks` | 执行质量规则并返回证据 | 处理动作需确认 |
| `preview_cleaning` | 预览规则、影响行数和派生版本 | 生成副本前二次确认 |
| `request_metric_contract` | 生成结构化指标合同 | 必须确认 |
| `execute_metric` | 执行计数、金额、平均和比例 | 合同确认后执行 |
| `execute_group_compare` | 分组汇总及组间比较 | 字段和指标确认后执行 |
| `execute_trend` | 按日/周/月/季度聚合趋势 | 时间字段和周期确认后执行 |
| `execute_top_n` | 分组聚合、排序与 Top N | 排序指标和 N 确认后执行 |
| `profile_relationship` | 识别键覆盖、基数、孤儿键和预估膨胀 | 键语义与输出粒度需确认 |
| `execute_join_pipeline` | 执行最多三表的受控关联与金额对账 | 每一步关系确认后执行 |
| `validate_result` | 执行范围、数值与对账校验 | 自动执行 |
| `export_evidence` | 导出结果、口径和代码 | 用户主动下载 |

工具只接受结构化参数，不接受任意 Python、任意 SQL、文件覆盖或系统命令。

## 5. Agent 状态机

```text
IDLE
  -> DATA_PROFILED
  -> PLANNING
  -> NEEDS_CLARIFICATION / NEEDS_APPROVAL
  -> READY_TO_EXECUTE
  -> EXECUTING
  -> VALIDATING
  -> COMPLETED / NEEDS_REVISION / NEEDS_JOIN_REVISION
  -> DATA_VERSION_CHANGED / UNSUPPORTED / FAILED
```

每一步保存输入数据版本、用户问题、工具参数、工具结果摘要、人工决定、耗时和错误信息。页面跳转不是状态完成的证据；只有对应工具返回并通过验收，状态才能前进。

## 6. 首版支持的经营分析

- 去重计数：订单数、客户数、商品数；
- 金额/总量：GMV、销售额、成本、库存量等；
- 平均指标：客单价、人均消费、平均库存；
- 比例指标：送达率、转化率、异常率；
- 分组比较：按地区、渠道、品类、客群汇总；
- 时间趋势：日、周、月、季度趋势；
- Top N：按明确指标排序后的前/后 N 个分组。

观察性数据只能输出关联和差异，不能自动生成因果结论。同比/环比和年度比较必须检查周期完整性。

## 7. 验收门

每项能力只有同时满足以下条件才算完成：

1. 支持一份此前未接入的 Excel/CSV，而非依赖 Olist 字段；
2. Agent 能识别意图、绑定真实字段并展示计划；
3. 口径不完整时阻止执行并提出具体澄清；
4. 数字来自确定性主工具，并由 DuckDB-WASM 使用独立 SQL 在同一数据版本上复算；跨场景基准仍可由独立 pandas 参考实现复核；
5. 结果包含数据范围、粒度、筛选条件、公式、校验和限制；
6. 错误、模型超时和不支持任务能够恢复或安全拒绝；
7. 单元、浏览器和端到端测试通过，无运行时异常。

## 8. 分阶段实现顺序

1. 已完成：Excel/CSV 数据画像、基础质量检查、清洗副本、四类单指标合同与受控计算。
2. 已完成：分组比较、时间趋势和 Top N 的统一确定性分析工具。
3. 已完成：`AnalysisSpec`、数据版本标识与 `TaskRun` 状态机，可记录工具结果、人工确认和失败。
4. 已完成：最多三表的关系画像、受控关联核心与 `N:N` 默认拦截。
5. 已完成：结果验证、隐私清理证据包、订单/营销/库存跨场景测评与浏览器主流程验证。
6. 已完成：交互式多文件关联页面、三表分步向导及来源行级金额对账；风险可传递到后续计算并阻止不安全聚合。
7. 已完成：D1 TaskRun 持久化、幂等并发控制、基础限流、条件式所有者隔离和本地备份恢复演练。
8. 待完成：聚合量比例、非常规金额字段人工指定、正式用户测试、公开部署、远程身份/D1 验收和集中告警。

项目对外应描述为“面向初级分析师的可信经营分析 Agent MVP”。多表工作流已经开放并完成自动化验证，但尚未经过正式用户研究，也不能描述为生产级企业数据平台。
