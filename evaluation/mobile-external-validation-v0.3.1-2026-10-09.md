# MetricGround v0.3.1 移动端外部身份验证记录

日期：2026-10-09

## 问题与修复

外部受邀身份首次在独立平板执行去重订单量时，主计算得到正确结果，但 TaskRun 因 `DuckDB 独立复核引擎启动超时` 失败。该失败说明 v0.3.0 的桌面验证没有覆盖移动设备首次加载大型 WASM 资源的冷启动条件。

修复后，DuckDB-WASM 1.32.0 的 Worker 与 WASM 由构建流程生成同源 gzip 资源，浏览器端解压后启动；指标页提前预热引擎，初始化上限调整为 60 秒。浏览器自动化新增移动视口、冷缓存和模拟 4G 网络条件。

## 已核实结果

| 项目 | 结果 |
|---|---|
| 访问身份 | 与项目所有者不同的外部受邀身份 |
| 设备 | 独立平板上的移动浏览器 |
| 测试文件 | `orders_quality_sample.csv`，11 行、5 列 |
| 指标 | 去重订单量 |
| 主计算 | 通过，结果为 10 |
| DuckDB 独立复核 | 通过，DuckDB-WASM 1.32.0，11/11 行进入计算 |
| TaskRun | 完成并持久化 |
| 工具调用 | `profile_dataset`、`run_quality_checks`、`execute_metric`、`validate_result`、`export_evidence` 均通过 |
| 交付 | Markdown 分析报告下载成功 |

自动化侧，生产构建下的移动端冷缓存与模拟 4G 受控计算回归通过，DuckDB 首次复核约 9 秒完成。

## 可以证明什么

- 真实外部身份可以访问受保护站点并完成自己的核心分析主链路；
- 移动端冷启动问题已经复现、修复，并有可重复回归保护；
- 主计算、独立 SQL 复核、TaskRun 审计和报告导出在该设备与样例上形成闭环。

## 不能证明什么

- 本次没有让外部身份读取项目所有者的 TaskRun，因此不能把它表述为“跨账号人工越权拒绝已验证”；
- 单设备单样例不代表所有机型、浏览器、文件规模或弱网条件均可用；
- 这不是 5 名目标用户无指导可用性测试，也不提供生产 SLA 证据。

为保护个人信息，验证记录不保存受邀账号邮箱。
