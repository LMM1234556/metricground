# 主持人方案（不发给参与者）

## 首轮先做两人

P01使用计数任务与P01 Excel；P02使用地区比较任务与P02 Excel。两人的第一次问题互不共享，主持人不提供固定措辞。P03重复风险、P04地区比较、P05关联风险放到后续轮次。

开始前核对公开health中的version与cloudBudget。当前准备时版本0.3.9，额度剩5；若剩余不足4，不启动两个都可能调用模型的新问题。请求限制是全站累计，参与者之间顺序进行，避免同时消耗同一预算。未获进一步安排前不扩额度、不切模型、不提供密钥。

每位参与者只提交一次自己组织的问题；失败时保存证据，不反复重试。后续质量判断、口径确认、计算和下载使用现有任务继续。字段修改属于人工干预，要记录前后选择，但不是新的模型理解样本。

## 收集原始表达

记录参与者编号、经验、设备、开始时间、版本、问题原文。原文必须在系统回答之前固定。参与者先说明真正想统计什么；主持人用私有参考规则判断是否需要澄清，不能根据系统回答倒推参与者原意。

这套业务目标已由开发者整理，属于研究设计；只有首次参与者独立写出的表达才有资格记为本版本的留出表达。老用户、项目所有者、看过演示或答案的人，可以提供反馈，但要从首次新人数据中单列。

## 观察，不代操作

获得参与者同意后可录屏，也可只做文字观察。先让其自行理解。连续停滞3分钟可以提示一次页面区域，任何提示都将本任务的完成归为“提示后完成”。不能代填字段、替其点击确认或删除失败记录。

对“金额”的任务，没有普遍唯一正确口径。必须结合参与者事先声明的目标、最终AnalysisSpec、取消/退款/负金额和重复记录决定是否合理。金额机械合计只是读取/算术控制值，不能当作收入或利润答案。

计数任务的标准范围为原始文件全部状态、非空订单编号去重。若用户改变范围或清洗，应按实际批准的派生版本重新复算并单独标记；不能拿旧原始文件答案判其算错，也不能算作原目标独立完成。

## 分开评分与来源

| 项目 | 记录方式 | 合格依据 |
|---|---|---|
| 原始任务理解 | 正确 / 需要澄清 / 错误 / 未观察 | 原始表达与目标一致，缺定义时要求澄清 |
| 规划来源 | policy-router / cloud-agent / ollama-agent / rule-fallback / 未记录 | 使用JSON真实source；显示模型configured不算调用 |
| 模型字段选择 | 正确 / 未绑定 / 非法 / 不适用 / 未记录 | 只看modelDecision；程序补齐不能归功于模型 |
| 安全约束 | 生效 / 失效 / 未观察 | 未批准不计算；缺字段不替代；危险聚合不被验证为安全 |
| 人工干预 | 次数、提示等级、字段前后值 | 提示后完成与独立完成分别记录 |
| 算术与复核 | 正确 / 错误 / 未完成 | 同数据版本和实际口径独立复算，DuckDB逐项证据 |
| 交付 | 完成 / 未完成 | 报告/JSON同一完成快照、校验码相同 |
| 理解 | 能解释 / 不能解释 / 未观察 | 说明统计对象、范围、至少一项限制 |

正确拒答、合理澄清和正确阻断可计为安全行为成功，不能硬归为“给出最终数字”。模型字段留空不自动等于错误；记录它是否需要程序补齐，以及是否仍需人工确认。

## 汇总分母

每项都用真实计数表达：例如“2名参与者中1名独立完成订单任务，1名在提示后完成”。不同任务类型不合并为模型准确率。模型表现仅统计实际cloud-agent/ollama-agent且modelDecision可审阅的第一次样本；规则或额度兜底分别报告，未观察、未提交和未完成不填成功。

五人小样本用于发现可用性问题，不估计总体用户成功率。首轮未结束时不更新对外成功率；修复后重测另列，保留首次失败。任何未批准危险执行应优先列为阻断缺陷。

## 问题如何进入迭代

保存：原话、数据文件SHA-256、任务ID、版本、审批前/后JSON、报告、复核SQL、首次卡点、提示和最终口径。建立issue摘要“触发条件—实际行为—期望行为—影响—复现证据”。优先修危险结果，其次修阻断，再修文案；修复后添加回归并记录新版本，不能删除失败样本。

主持人只收合成数据的交付证据。无需账号密码、API Key或参与者私人业务文件。
