# 后三人补充测试：主持人使用，不发给参与者

准备日期：2026-10-12。软件 v0.3.10，证据格式 1.4。不修改路由，不扩模型额度，不充值。材料准备不代表参与者已完成。

## 顺序与时间

P04 → P03 → P05，逐个进行，每人一个主任务，最多 10 分钟。时间预算不是已观察用时。开始前用 /api/health 核对版本和 cloudBudget；准备时剩余 3 次 HTTP 请求，不是 3 个完整问题，每个云问题可能需要 2 次请求。P04 优先使用剩余额度；主持人准备材料和核对参考值不调用模型。

每人首次只提交一次自主组织的问题，回答前保存原话及真正目标。后续控件、人工修改和提示分开记录。停滞超过 2 分钟可以提示页面位置一次，标为“提示后完成”；不代填、不替人确认。可提前停止，失败与正确阻断都保留。

主持人私有算术参考（2026-10-12用 Python 读取原 CSV 独立计算，不发给参与者）：订单表 4 行、明细表 5 行，原订单金额机械合计 410。以订单表为左表、order_id 为键的左关联输出 5 行，直接相加订单金额得到 530，多出的 120 来自同一订单匹配两条商品明细。O-1004 无匹配明细，O-X 是无法匹配订单的明细编号。若参与者选内关联，输出 4 行、订单金额机械合计 470：排除了原订单的 60，同时重复附着了 120，不能仅看净差额归因。不同关联或主动清洗以实际版本重新复算；参考数字不是推荐业务口径。

## 模型来源，不强迫全部用模型

- cloud-agent 且 modelDecision 可审阅：才计真实模型规划样本；程序补齐字段不能计模型选对。
- policy-router：规则样本，不是模型调用失败。
- rule-fallback：检查 fallbackReason，区分额度、调用失败与规则兜底；不计模型成功。
- 预算前后计数只是补充。失败调用可能消耗额度，无 token 记录不等于零费用。

若 P04 首次命中规则，保留它，不让参与者反复改写以假装独立表达。可在三人主任务结束后、仍有至少 2 次额度时，另做一次主持人控制的模型路径补充探针。它是已知措辞的工程测试，不是新人自然语言成功样本。

主持人探针仅限一次（使用 P04 文件）：

> 请理解这份数据，为团队决定下一步优先跟进哪一片市场提出分析计划，说明建议使用的字段和需要我确认的业务定义；先不要计算。

准备时只在本地检查此措辞未命中强规则，没有请求模型。实际 cloud-agent、字段、澄清和预算仍须看返回证据；不得提前写成通过。不足 2 次额度则不做，标记“本轮模型路径未观察”，不追加充值或修改认证。
